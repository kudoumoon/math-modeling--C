# 训练前数据与防泄漏规约

## 1. 目标

Q3、Q4 面向真实运行决策，不能假设能够看到未来完美数据。预测器的价值必须通过“预测误差 + 下游滚动优化效果”共同判断，而不是只比较单一回归指标。

## 2. 强制时间语义

1. 十分钟步长为 `Δt = 1/6 h`。
2. 附件的日内顺序从 `0:10–0:20` 开始，最后一格为次日 `0:00–0:10+1`。
3. `0:00+1` 必须映射为日期 `d+1` 的 `00:00–00:10`，不得整体前移或后推。
4. 建议生成唯一时间戳 `interval_start` 和 `interval_end`，并在进入训练前检查时间戳严格递增、无重复、无缺口。

## 3. 决策时可用信息集

- 对任一决策时刻 `t`，特征只能来自 `t` 及其之前已经发布或观测的数据。
- 预测层必须保留题目规定的多时刻信息更新语义；不同更新时间得到的预测版本不得互相穿越。
- 未来真实负荷、未来真实光伏、未来真实电价和事后形成的全日统计量禁止作为输入。
- 若某个字段的发布时间不明确，先按“在目标时刻不可用”处理，并在数据字典中标记，不能乐观假定可见。
- Q1 的单日固定初始 SOC 规则不得直接搬到 Q2–Q4；滚动阶段的 SOC 必须跨日连续传递。

## 4. 数据切分和特征处理

- 训练集、验证集和测试集严格按时间先后切分，禁止随机打乱后切分。
- 推荐使用扩展窗口或滚动窗口回测；每个回测折只允许用该折预测起点之前的数据拟合模型。
- 标准化器、缺失值填补器、特征选择和降维器只能在训练窗拟合，再应用到验证窗和测试窗。
- 滞后量、滚动统计量和周期编码应在统一时间索引建立后生成；滚动统计必须显式 `shift`，防止包含当前目标或未来值。
- 模型选择和超参数搜索只看验证窗口；测试窗口只用于最终一次报告。

## 5. 分层基线与 GPU 模型准入

模型必须按以下顺序比较：

1. 持久性预测、同周期朴素预测；
2. 周期均值/线性或正则化回归；
3. 树模型；
4. 只有在前述基线上获得稳定增益后，再进入 TCN、LSTM/GRU、N-BEATS、TFT 等 GPU 候选。

复杂模型不能仅凭单次随机划分胜出。至少要求多个滚动窗口稳定优于基线，并通过因果回放、消融实验和回退门槛。

## 6. 评价闭环

预测层至少报告 MAE、RMSE、分位数覆盖率或区间覆盖率，并按月份、日内时段和天气/波动状态分组。

决策层至少报告：

- 年度总购电成本；
- 相对完美信息参考界的 regret；
- 紧急购电量及尾部风险；
- SOC、功率、能量平衡和充放电互斥违规次数；
- 相对朴素预测基线的成本改善。

最终模型以滚动回测中的决策价值为主判据。若复杂预测器没有带来稳定的成本改善，必须回退到更简单且可解释的基线。

## 7. 训练产物建议

后续建议将派生产物放在以下目录，且不要覆盖 `data/`：

```text
src/             数据管道、模型与评估代码
configs/         训练和回测配置
artifacts/       模型权重、标准化器和特征清单
predictions/     带 issue_time/target_time 的预测
reports/         指标、消融与下游成本报告
```

每次实验记录随机种子、输入文件哈希、代码提交号、依赖版本、GPU/驱动版本和唯一复现命令。
