# Q3/Q4 因果滚动收益验证

## 验证边界

本报告采用 2025-02-01—2025-12-31 的完整 10 分钟账本。模型在每个日界面只使用当时已经完成的观测：负荷和价格采用漂移感知在线校正，光伏严格按题目规定的 0/6/12/18 时点释放；Q4-2 的光伏使用因果 lag-7 基线，Q4-3 使用官方发布预测。实际价格只进入事后结算账本，不进入决策。

滚动执行器保持原 LP 主干：电量上下界、充放电效率、功率约束、期末能量约束和 5 倍应急电价均在逐日执行中保留。

## 经济门控

同日更新先形成候选采购曲线，再用过去最多 56 个已完成日的同槽位净负荷残差做反事实场景。只有当候选更新扣除 1.5 倍上调费/0.5 倍下调费后的历史平均收益和 25% 分位收益都为正时，才允许进入最终采购曲线；否则回退到日初 LP 计划。这是因果的经济选择，不是用当天未来实际值调参。

## 审计期结果（2025-07-01—12-31，184 天）

|场景|基线|经济门控滚动|现金成本下降|应急电量变化|
|---|---:|---:|---:|---:|
|Q3（固定电价）|8,191,697|8,164,059|27,638（0.338%）|80,882 → 52,696 kWh（−34.85%）|
|Q4-2（lag-7 光伏）|8,870,898|8,870,898|0|84,084 → 84,084 kWh|
|Q4-3（官方光伏）|8,817,239|8,790,099|27,140（0.308%）|79,324 → 51,893 kWh（−34.58%）|

这里的基线是 `adaptive_no_updates`，滚动策略是 `adaptive_rolling`；另有 static 预测器作为独立对照。Q3/Q4-3 的更新分别通过 186/181 个六小时门控，说明门控没有把所有更新一律关闭；Q4-2 没有新增可用的同日光伏信息，因此两种策略严格相同。

开发期（2025-02-01—06-30）也用同一规约运行，但不用于最终收益宣称。开发集的 alpha 扫描在独立账本中偏向 0.85；由于部署规约要求审计期稳健，滚动主线仍固定使用 alpha=0.70，避免把开发期选择当成未来信息。

## 统计证据与解释

逐日现金成本差采用 3、7、14 日块 Bootstrap，并输出到 `reports/q3_q4_block_bootstrap.csv`；月度成本/应急量分解输出到 `reports/q3_q4_monthly_decomposition.csv`；信息消融（无更新 vs 经济门控更新）输出到 `reports/q3_q4_information_ablation.csv`。审计期平均日收益为 Q3 150.21、Q4-3 147.50，但 95% 块 Bootstrap 区间均跨过 0，因而论文中应表述为“样本期内正向、但不显著”，不能写成普适保证。

此前未加经济门控的直接调整虽然降低了应急量，却因调整费使总成本上升；这次结果证明经济目标必须接入调度器，而不能只看预测误差或应急电量。

## 当前结论与下一步

现阶段建议采用“因果预测 + 漂移感知适配 + LP + 经济门控”的统一小模型作为候选方案。由于收益置信区间仍跨 0，暂不把更复杂的 GPU 统一模型直接替换进主线。下一步才在 H100 上以相同滚动账本、相同随机种子和相同审计期训练 challenger；只有在现金成本、应急量和 Bootstrap 区间同时改善时才替换。
