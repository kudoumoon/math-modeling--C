## 3. 阶段 1-5 工作分解

### 阶段 1：仓库同步与证据保全

1. 合并远端 Q1、Q2 v2、Q3 v2、Q4 归档和本地预测器，不覆盖任一历史版本。
2. 保留 `VERSION_STATUS.json` 作为机器可读入口，保存源文件、结果文件和配置哈希。
3. 新版本统一使用 `program`、`results`、`figures`、`others` 四类目录。
4. 失败实验写入独立运行目录并标记失败原因，不删除、不改名为成功版本。
5. 每个完成版本单独提交并推送；未通过审核的版本不得标记 `OFFICIAL`。

### 阶段 2：建模技能与统一契约

1. 使用已安装的 `math-modeling` skill 作为过程检查清单，不把 skill 文本视为题目权威。
2. 根目录维护本报告与 `术语表格.md`，冻结物理、时间、信息、结算和版本语义。
3. 编程前执行独立只读 M1 审核；最小真实链路后执行 P1；完整结果、图表和复现清单后执行 P2。
4. 任一实质性模型、数据、代码或账本变更都会使对应旧审核失效。

### 阶段 3：现有基线复现与审计

1. Q1：检查输入、目标值、能量平衡、SOC 回放和模板回读。
2. Q2 v2：先运行测试，再运行第 31 日隔离烟雾实验，最后才允许 334 天完整复现。
3. 审核 Q2 v2 的零点信息边界、`0:00+1` 跨日槽、Battery A 实时反馈解释、初始 SOC 和年度末资产。
4. 核对全部费用由区间账本求和得到：普通购电费、紧急购电费、总费和剩余供给分别记录。
5. Q3/Q4 历史目录只验证其错误上游事实和可复用模块，不复现为正式结果。

### 阶段 4：Q2 v3 预测器价值隔离

实验纪律：

- 预测模型和是否启用在线修正只在开发期确定；审计期只能作回顾性一次披露。
- Q2 不得使用附件 3 的官方日内 PV 预报，因为该信息属于 Q3。现有 96 分预测器的 `pv_hourly` 通道因此不能接入 Q2。
- 每个预测器使用自身在当时产生的历史残差；禁止给新预测器套用旧预测器残差。
- 先比较共同可执行样本，再报告全量运行；缺标签不能删除预测请求。
- 必报总现金费用、普通购电费、紧急购电费与电量、剩余供给、尾部日费用、求解时间、期末 SOC 和统一资产调整费用。
- 主要判定使用同日期配对费用差及连续日块 Bootstrap；预测 MAE/RMSE 只作解释。
- B1 身份不再做候选筛选：负荷和PV均固定 `HistGradientBoostingRegressor(loss="squared_error", learning_rate=0.06, max_iter=180, max_leaf_nodes=31, min_samples_leaf=40, l2_regularization=1.0, early_stopping=False, random_state=20260912)`。MAE/RMSE只作报告，不用于改变 B1 身份。
- 两个HGB通道的值特征固定为日滞后1/2/7/14/21/28、3/7/14/28日滚动均值与标准差、最近4个同星期均值；日历特征固定为槽位/星期/年内日的正余弦、月份和周末标记。禁止其他数据列，PV直接预测附件2实际PV，不读取附件3。

## 4. 统一物理模型

每日 144 个十分钟区间，功率乘 `DT=1/6 h` 后转为 kWh。储能含 145 个边界状态：

\[
q_t+h_t+v_t\Delta t+d_t=l_t\Delta t+c_t+w_t,
\]

\[
E_{t+1}=E_t+0.9c_t-d_t/0.9.
\]

其中 `q` 为普通购电量，`h` 为紧急购电量，`v/l` 为 PV/负荷功率，`c/d` 为交流侧充放电量，`w` 为剩余供给。约束为：

- `1200 <= E_t <= 10800 kWh`；
- `0 <= c_t,d_t <= 5000/6 kWh`；
- 充放电效率均为 0.9，往返效率为 0.81；
- 普通购电按 `p_t q_t`，紧急购电按 `5 p_t h_t`；
- `w` 可能同时包含未消纳光伏和未使用普通购电，未做来源分账时只能称“剩余供给”。

Battery A 的合法解释是实时反馈控制器：每个区间开始时读取当前可见的实际负荷、PV 和 SOC，按已确认普通购电量执行充放电并补紧急电。它不是全天预知控制。正式报告必须写明此理想即时测量假设，并以一槽延迟作敏感性检查。

## 5. 时间与信息合同

题面“0:00制定/0:00与24:00储量”、附件时间点和模板区间标签存在一槽歧义，不能声称三者天然一致。冻结决策表如下：

|解释|输入映射|优化覆盖|状态真实时刻|用途|
|---|---|---|---|---|
|A：模板左端点（主）|第1项`0:10`直接用于模板`0:10-0:20`；末项用于次日`0:00-0:10`|当日00:10至次日00:10|`E_0`=当日00:10，`E_144`=次日00:10|正式模板主结果；模板“0:00/24:00储量”字段注明为名义字段，与真实状态时刻相差10分钟|
|B：附件右端点（敏感性）|跨日左移：`B[d,0:143]=A[d,1:144]`，`B[d,143]=A[d+1,0]`|同上|同上|检验附件时间点若表示区间右端时的费用影响，不与A混表|

选择 A 是因为附件5明确给出了144个购电区间，主结果优先逐行遵守交付模板。该选择不能消除官方材料的状态字段歧义，所以论文必须披露10分钟偏移，并报告 B。指定时段和4小时汇总一律按模板行分组，不把 `E_0/E_144` 伪称为真实00:00/24:00观测。Q2-Q4 的 B 映射禁止逐日 `np.roll`；因附件不含2026-01-01首槽，B敏感性只比较2025-02-01至2025-12-30，12月31日不填造数据。Q1是无限重复的固定典型日，可在明确周期假设下以第1项补最后一槽。

Q1 隔离复算证据：A 解释得到购电量 59,482.698998 kWh、费用 35,126.948589 元，模板回读与全部物理检查通过；B 解释按固定典型日周期左移价格、负荷和PV，得到相同购电量和 35,129.731923 元。B 比 A 高 2.783333 元（0.0079%），说明本实例总费对该歧义不敏感，但指定时段轨迹仍须按各自解释分开。

在自然日零点生成新计划时，上一计划日最后一个槽尚未完成。新计划只能使用上一槽开始前已知 SOC、已确认合同和已发布预测估计新计划初值；不能提前读取上一槽结算后的真实 SOC。执行到相应时刻后才允许使用实际状态校正。日志必须同时保留 `planned_initial_energy_kwh` 与 `executed_initial_energy_kwh`，并记录估计来源的预测版本。

## 6. 版本、审核与停止条件

新目录命名固定为：

```text
solutions/Q2_V3_CAUSAL_FORECAST/{program,results,figures,others}
solutions/Q3_V3_ALIGNED/{program,results,figures,others}
solutions/Q4_V1_ALIGNED/{program,results,figures,others}
```

每个版本至少包含：版本身份 JSON、配置、环境、输入/源码/结果哈希、运行命令、逐段结果、汇总、图表、测试记录和审核回执。Agent1 负责实现和实验；Agent2 保持只读，按冻结评分表给出证据、扣分、硬阻断和 `PASS/FAIL/BLOCKED`。

内部 100 分以一等奖级完整性为方向，但不代表获奖概率。停止条件是每个正式问题版本均达到至少 90 分且硬阻断为零。未满足时按 Q1 -> Q2 -> Q3 -> Q4 -> 审核顺序继续；预测器只在真实经济回放支持时同步升级。

## 7. 硬阻断与回退

出现以下任一项不得发布正式版本：未来信息进入决策；时间窗口错位；Q3/Q4 读取错误上游；账本不守恒；依据审计期反复择优；通过删除请求改变评分样本；结果无法由冻结代码与输入复现；哈希或模板身份冲突未解释。

升级模块未通过时采用局部回退：预测器无稳定收益则回退 Q2 v2 预测；在线调整无收益则 Q3 保持原合同；动态价格预测无收益则保留合法朴素价格预测。回退不删除失败证据，也不降低审核标准。
